## ★ 이번에 실측한 게이트 결함 4종 (재발 방지)

메모리에 이미 기록돼 있던 패턴을 그대로 재발시켰다. 게이트를 새로 짤 때마다 확인할 것.

1. **진료과명을 STRONG 에 태움** → `한의원` 162,200 · `신경외과` 64,060 · `신경과` 42,650
   단독 통과. 지역광고 조합이 대량 유입된다. → 전부 AMBIG 강등.
2. **AMBIG ∩ MEDCTX 자기만족** — `한의원` 이 양쪽 집합에 있어서 자기 자신으로 문맥조건을
   충족시켰다. → `MEDCTX_EFF = MEDCTX - AMBIG` + 문맥토큰 ≠ AMBIG히트 강제.
3. **단일 글자 AMBIG 금지** — `코`→지르코니아크라운가격·코엔자임Q10·코감기약,
   `눈`→인공눈물가격·티눈병원, `목`→발목터널증후군, `턱`→턱보톡스효과.
   한 글자는 어떤 문맥어와도 붙는다. → 2글자+ 복합형(`목통증`·`눈부심`)만.
4. **해부학 총칭을 AMBIG 에 넣음** — `정맥`+증상→하지정맥류증상 25,300, `동맥`→동맥경화증상,
   `신경`+치료→치아신경치료, `두피`+관리→두피관리. 그 어휘가 필요한 희귀질환명은
   이미 STRONG 에 전량 있으므로 빼도 손실 없다.

**신규 부분문자열 지뢰 5종** (기존 백지·천마·시호·황금·이명·유두통에 추가):
- `뒷골` → **뒷골목 · 뒷골생오리 · 뒷골목돗갈비**(식당/거리). `뒷골당김/뒷골통증` 복합형만.
- `정수리` → **정수리볼륨핀 · 김신영정수리템 · 정수리흰머리**(미용/쇼핑).
- **`이형성증`** — 희귀질환 별칭 생성기가 **어간 없는 순수 접미어**를 별칭으로 만들었다
  (원본 "…감각신경성 청력 상실 및 골격 이형성증") → 자궁이형성증·골수이형성증후군 오통과.
  **접미 유형어 단독 금지**: 증후군/기형/결핍증/이상증/경화증/위축증/근육병/신경병증/장애.
- **`우주여행`** — ICHD-3 "우주비행에 기인한 두통"에서 핵심명사만 추출된 것 →
  **준궤도우주여행티켓 5,160 · 버진갤럭틱우주여행** 이 두통 시드로 올라왔다.
  서술형 ICHD 항목에서 명사구를 뽑을 땐 두통 복합형만 남길 것.
- `부근` — 별칭 생성기 정크(→'부근에'). 2~3글자 별칭은 전부 금지.
- 의료문맥에서 **`수술`·`시술` 제거** — `눈`+`수술/후기/비용` 이 눈처짐수술·눈썹거상술후기를
  통과시켰다. 한의원은 수술을 하지 않으므로 전환 0 이다.

**★ 역추적법이 이 모든 걸 1분에 잡는다** — 정크 키워드 × STRONG/AMBIG/MEDCTX substring
매칭으로 원인 앵커와 그 **출처**(어느 소스에서 온 어휘인지)까지 특정된다. 게이트를 만지면
매번 상위 40개를 육안으로 보고 이 역추적을 돌릴 것.

## ⛔ 등록이 막혀 있다 — 워커 이벤트 루프 블로킹 (2026-07-30 실측)

`seed-explode-register` 가 **매번 정확히 8.1~8.2초**에 `{"queued":true,"async":true}` 만 돌려준다
(= `main.py:646` 프록시 read timeout 8.0s 경로). 4회 연속 재시도 + 드라이버 90회 재시도(30분)
전부 실패. **pool 55,423 불변 · seed_explode run 0건.**

**간헐적 워커 포화가 아니다**:
- 핸들러(`naver_ad.py:7778`)는 `background_tasks.add_task` 후 **즉시 return** 하는 구조라
  정상이면 0.3s 에 `started:true` 가 온다(2026-07-27 실측치).
- `register` 크론은 45~90초마다 정상 동작(`no_pending`) → 워커 프로세스 자체는 살아있다.
- 그런데 HTTP 요청이 8초 안에 서비스되지 않는다 → **워커 uvicorn 루프가 장시간 블로킹**.
  유력 원인 = 자동완성 마이닝 틱이 **계정당 3~4분** 루프를 점유(`[[project_jamo_surface_mining]]`
  에 기록된 구조: 9계정 라운드로빈, 틱당 1계정). 그 3~4분 동안 모든 오프로드 요청이 8s 로 죽는다.
- ⚠️ `flyctl apps restart` 로는 안 고쳐진다(2026-07-27 실측).

**근본 해결(백엔드 수정 + 배포 필요, 미착수)**: `seed-explode-register` 를
`_WORKER_OFFLOAD_PATHS`(main.py:601) 에서 빼고, 이미 같은 이유로 제외된 3개 엔드포인트와
동일한 패턴을 쓴다 — `ceiling-backtest` 방식(**app 핸들러가 /data 에 요청파일만 쓰고 worker
워치독이 claim 해 실행**; 제어는 HTTP, 실행 트리거는 공유 볼륨). 단순히 목록에서 빼기만 하면
app 이벤트 루프를 점유해 **로그인 hang 이 재발**한다([[project_login_hang_worker_offload]]).

**우회(차선)**: `POST /keyword-pool/seeds` 는 오프로드 목록에 없어 app 에서 바로 처리된다.
단 `monthly_total=0` 으로 박히므로 register 의 `claim_pending(min_volume=10)` 에 직접 안 걸리고,
**collect 크론이 user_seed 를 시드로 재소비**하는 경로로만 서서히 등록된다(며칠). 풀 백로그를
늘리는 부작용이 있어 이번 세션에서는 적용하지 않았다 — 사용자 판단 사항.
