# 검색 여정 맵 (Search Journey Map) — 설계서

> 업종 하나를 넣으면 **구매 여정 5단계 × 단계별 키워드 × 검색량 비율 × 우리 커버리지**를 뽑는다.
> 리스닝마인드 허블의 대안이되, 클릭스트림 없이 만든다.

작성 2026-08-10 / 상태: 설계 확정 전, P0 미착수

---

## 0. 결론 요약

- 엔진 부품의 **70%는 이미 이 저장소에 있다.** 새로 만들 건 "여정 조립기" 한 층과 캐시 전략뿐이다.
- 무료화가 가능한 이유는 원가가 싸서가 아니라 **여정 맵이 업종 단위 공용 자산**이기 때문이다.
  "미용피부과"를 100명이 조회해도 계산은 1회다. 개인화되는 층(내 블로그 커버리지)만 사용자별로 돈다.
- 우리가 리스닝마인드보다 잘하는 지점은 정밀도가 아니라 **다음 행동**이다.
  맵 → 결손 지점 → 원고 → 자동발행 → 순위 되먹임까지 한 줄로 붙는다(`BLOG_AUTOPOST_SPEC.md`와 직결).

### 못 만드는 것 (명확히 인정하고 시작)
클릭스트림(A 검색 → 30분 뒤 B 검색). 패널 데이터라 복제 불가.
→ 대신 **수식어 패턴 · 검색량 피라미드 · SERP 구성** 세 신호로 단계를 배열한다(§3).

> 신규 업종은 콜드스타트지만, 의료·미용은 사실상 즉시 뽑힌다.

## 2. 산출물 정의 (이걸 먼저 고정한다)

원장님 화면에 뜨는 최종형. 이걸 못 그리면 나머지는 의미 없다.

```
[업종: 미용피부과]

① 인지        검색량 비율 34%   키워드 412개   우리 커버 3개  ▁▁▁ 
   "모공 넓어짐 원인", "여드름 흉터 왜 생기나"
② 탐색        24%   1,108개   우리 커버 11개  ▂▂▂
   "모공축소 방법", "레이저 종류 차이"
③ 비교        17%   631개     우리 커버 2개   ▁▁▁   ← 결손 최대
   "포텐자 비용", "실비 되나요"
④ 검증        16%   889개     우리 커버 27개  ▆▆▆
   "포텐자 후기", "부작용", "잘하는 곳"
⑤ 행동        9%    2,140개   우리 커버 140개 ███
   "강남 모공 피부과", "OO의원 예약"

▶ 병목: ③ 비교 단계. 검색량 17%인데 커버리지 0.3%.
   → 추천 원고 5건 [생성하기]
```

핵심은 표가 아니라 **"어디가 비었는가" 한 문장**이다. 그게 판매 포인트다.

## 3. 클릭스트림 없이 단계를 배열하는 법

### 3.1 신호 ① 수식어 패턴 — 대상어/의도어 분리가 전부

한국어 검색어는 `대상 + 의도어` 구조다. **의도어만 보면 단계가 거의 결정된다.**

```
모공축소 + 비용   → 비교
모공축소 + 후기   → 검증
강남 + 모공축소   → 행동
```

현행 `KeywordClassifier.classify()`의 한계 두 가지를 여정 엔진에서는 반드시 고친다.

1. **유형이 flat이고 순서가 없다.** 여정은 순서가 본질이므로 `stage: 1~5` 정수를 부여한다.
2. **substring 매칭이라 오판한다.** 메모리에 실제 사고가 기록돼 있다 —
   `백선`(완선 축) / `남성장`→`강남성장클리닉` / `유두통`이 `두통`으로 / `키즈`의 `키`가 height 아님.
   → 여정 엔진은 **먼저 토큰 분해 후 의도어 슬롯에서만** 매칭한다. 원문 substring 매칭 금지.

새 사전 파일: `data/journey_lexicon.py`

```python
# 업종 무관 공통 의도어 — 이 한 벌이 대부분을 커버한다
STAGE_LEXICON = {
    1: {  # 인지 (Awareness) — 문제를 막 인식
        "suffix": ["란", "이란", "뜻", "의미"],
        "token":  ["원인", "증상", "왜", "초기", "전조", "생기는이유", "구분"],
    },
    2: {  # 탐색 (Consideration) — 해결책 종류 파악
        "token": ["방법", "종류", "차이", "치료", "관리", "예방", "효과", "vs", "비교"],
    },
    3: {  # 비교 (Evaluation) — 돈·조건 따짐
        "token": ["비용", "가격", "얼마", "보험", "실비", "급여", "비급여",
                  "할인", "이벤트", "기간", "횟수", "회복기간"],
    },
    4: {  # 검증 (Validation) — 남의 경험·리스크 확인
        "token": ["후기", "리뷰", "부작용", "실패", "재발", "잘하는곳", "유명한",
                  "추천", "명의", "순위", "실제"],
    },
    5: {  # 행동 (Action) — 오기 직전
        "token": ["예약", "상담", "문의", "당일", "야간", "주말", "가까운"],
        "slot":  ["REGION", "BRAND"],   # 지역명·브랜드명이 붙으면 무조건 5단계
    },
}

# 업종별 오버라이드 — 여기만 갈아끼우면 새 업종
INDUSTRY_OVERRIDE = {
    "미용피부과": {
        "anchor": ["모공", "여드름", "리프팅", "색소", "제모", ...],   # 대상어(온도메인 판정)
        "stage_hint": {"흉터": 1, "지속기간": 3, "다운타임": 3},
        "trap": ["모공청소기", "여드름패치"],   # 쇼핑 드리프트 차단
    },
}
```

> **`trap`은 선택이 아니라 필수다.** 리베리에서 드리프트 1만~1.8만(보충제·화장품쇼핑),
> 해울에서 최근 등록 95%가 마스크·하드디스크로 오염된 전례가 있다.
> 여정 맵은 광고 등록이 아니라 화면 출력이라 피해는 작지만, 화면이 오염되면 신뢰가 죽는다.

**커버리지 목표: 규칙으로 70~80%.** 나머지 미분류 잔여분만 LLM으로 보낸다(§5 원가).

### 3.2 신호 ② 검색량 피라미드 — 사전의 자가 검산

정상 업종은 `단계1 ≥ 단계2 ≥ 단계3` 형태의 감쇠를 보인다(단계5는 지역 조합 때문에 **키워드 개수**는 폭증하되 **검색량**은 작다 — 개수와 검색량을 반드시 분리 집계할 것).

순서가 뒤집히면 사전이 틀린 것이다. → `assemble()` 마지막에 피라미드 검산을 넣고, 위반 시 응답에 `warnings[]`로 노출한다. **자동 보정은 하지 않는다**(틀린 사전을 숨기게 된다).

### 3.3 볼륨 함정 — 가장 흔한 오독

`monthly_total == 10` 은 네이버의 `<10` 플레이스홀더다(메디론에서 실측 — 등록 25,593개 중 실검색량 >10은 11개뿐이었다).
비율 계산에서 `10`을 그대로 더하면 **꼬리가 몸통을 이긴다.**
→ 집계 시 `vol == 10` 은 `2`로 감가하거나 별도 버킷 `sub10_count`로 분리한다. 사용자에게는 "저볼륨 롱테일 N개"로 표시.

### 3.4 신호 ③ SERP 구성 — 상위 30개만 검증

같은 키워드라도 결과 상단이 지식인·블로그면 정보형, 파워링크·플레이스면 거래형이다.
`serp_difficulty.py`가 이미 블로그탭 상단을 파싱하므로 **탭 구성 파싱만 추가**한다.

비용이 드는 유일한 층이므로 **단계별 대표 키워드 상위 6개씩, 총 30개로 상한**. 그 결과로 규칙 사전의 오배정을 사후 교정하고, 교정 내역을 사전에 되먹인다(학습 루프는 `keyword_analysis_db`의 `save_keyword_type` 자산 재사용).

## 4. 파이프라인

```
업종 문자열
  │
  ├─ (a) 코퍼스 히트: naverad_keyword_pool 에서 anchor 토큰 매칭 → 즉시 수만 행    ← 가장 싸고 빠름
  ├─ (b) keywordstool 연관키워드: anchor 시드 → 콜당 1,200행 + 검색량
  └─ (c) 자동완성/자모: build_jamo_variants(anchor) → 꼬리 채굴 (포화 판정 뒤집는 표면)
        │
        ▼ 병합·정규화(공백/대소문자/중복)
        ▼ 온도메인 게이트 (anchor AND NOT trap)          ← 오염 차단
        ▼ 볼륨 부착 (미보유분만 keywordstool 조회)
        ▼ 단계 배정: 토큰분해 → STAGE_LEXICON → 미분류는 LLM 배치
        ▼ 피라미드 검산 → warnings[]
        ▼ SERP 검증 (대표 30개)
        ▼ 캐시 저장 (업종 단위, TTL 30일)
```

**핵심 설계 결정: 실시간 계산 금지.**
`winner_keywords` 사태의 교훈이다 — 실시간 계산 1건이 이벤트 루프를 점유해 `/health`를 30초로 밀고 전 서비스를 마비시켰다.
여정 맵은 **worker 사전계산 + 캐시 조회**만 API로 노출한다.

- 조회 API는 캐시만 읽는다. miss면 `202 + job_id` 반환하고 큐에 넣는다(즉석 계산 절대 금지).
- 무거운 POST는 `_WORKER_OFFLOAD_PATHS` 등록 필수(로그인 hang 근본원인과 동일 함정).

## 5. 원가와 무료화 구조

| 항목 | 원가 |
|---|---|
| 코퍼스 조회 | 0 |
| keywordstool | 0 (무료 API, 레이트리밋만 주의) |
| 자동완성/자모 | 0 (Fly IP는 로컬 대비 50~500배 느림 — 로컬/워커 분리 고려) |
| LLM 분류 | 미분류 20% × 3,000개 ≈ 수백 원 |
| SERP 검증 | 30콜 |
| **업종 1개 전체** | **1,000원 내외 · 1회성** |

무료화의 진짜 근거는 원가가 아니라 **캐시 재사용률**이다.

- 여정 맵은 사용자와 무관한 **업종 공용 자산** → 조회 1,000회에 계산 1회
- 리스닝마인드는 사용자별 세션·클릭스트림이라 이 구조가 원천적으로 불가능하다.
  우리는 무료로 뿌리고 그들은 못 뿌린다. **이게 유일한 비대칭 우위다.**

### 게이팅 (무료로 뿌리되 어디서 돈을 받나)

| 티어 | 제공 |
|---|---|
| **비로그인 무료** | 5단계 맵 · 단계별 검색량 비율 · 단계별 대표 키워드 20개 · 병목 진단 1문장 |
| **로그인 무료** | 전체 키워드 표 · 단계 필터 · CSV 내보내기 |
| **유료** | **내 블로그 커버리지 오버레이** · 결손 키워드 목록 · 난이도(뚫리는가) · 원고 생성 · 자동발행 |

무료 구간이 "쓸모없는 맛보기"가 아니라 **그 자체로 완결된 리포트**여야 유입이 돈다.
개인화 층이 시작되는 지점이 자연스러운 결제선이다 — 블러 처리로 막는 게 아니라, 무료 화면에는 애초에 "나"가 없다.

## 6. 커버리지 오버레이 (유료층 · 우리만 가능)

리스닝마인드는 맵까지 주고 끝난다. "그래서 뭘 써야 하나"는 마케터 몫이다.
우리는 이미 순위 조회와 블로그 지수를 갖고 있으므로 한 층을 더 얹는다.

```
단계별 키워드 × rank_checker → 우리가 1p에 있는 개수
                × exposure_ceiling → 우리 지수로 뚫리는 개수
결손 = 검색량 비율 높음 AND 커버리지 낮음 AND 뚫림
     → BLOG_AUTOPOST_SPEC 의 원고 생성 입력으로 그대로 투입
     → rank_tracker 되먹임으로 다음 회차 커버리지 갱신
```

이 루프가 완성되면 판매 문장이 이렇게 바뀐다:
"키워드를 보여드립니다" → **"비어 있는 3단계를 저희가 채워드립니다."**

## 7. GEO와 같은 자산으로 설계할 것

검색 의도 맵은 AI 답변 최적화(GEO)의 입력값 그 자체다.
"어떤 인텐트에서 우리 브랜드가 안 잡히는가" = "AI가 우리를 언급하지 않는 지점".
따로 만들지 말고 `journey_maps` 하나를 공유 자산으로 두고, GEO는 그 위에 "AI 답변 점유" 컬럼을 추가하는 방식으로 붙인다.
리스닝마인드가 GPT리뷰·GEO로 확장 중인 것도 같은 이유다.

## 8. 데이터 모델

```sql
CREATE TABLE journey_maps (            -- 업종 단위 공용 캐시
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    industry TEXT NOT NULL UNIQUE,     -- 정규화된 업종 키
    lexicon_version TEXT NOT NULL,     -- 사전 버전 (사전 갱신 시 일괄 무효화)
    total_keywords INTEGER,
    total_volume INTEGER,
    sub10_count INTEGER,               -- <10 플레이스홀더 분리 집계
    stage_json TEXT,                   -- 단계별 집계 + 대표 키워드
    warnings_json TEXT,                -- 피라미드 검산 위반 등
    built_at TIMESTAMP,
    expires_at TIMESTAMP
);

CREATE TABLE journey_keywords (
    map_id INTEGER NOT NULL,
    keyword TEXT NOT NULL,
    stage INTEGER,                     -- 1~5
    confidence REAL,
    monthly_total INTEGER,
    is_sub10 INTEGER DEFAULT 0,
    source TEXT,                       -- corpus | keywordstool | autocomplete | jamo
    classified_by TEXT,                -- rule | llm | serp
    UNIQUE(map_id, keyword)
);
```

커버리지는 여기 저장하지 않는다(사용자별이므로 조회 시 조인).

## 12. P0 실측 결과 (2026-08-10)

두 업종을 같은 사전으로 돌렸다. 두 번째는 **대조군**이다 — 사전 버그와 시장 성질을 가르기 위해.

| | 미용피부과 | 두통한의원 |
|---|---|---|
| 수집(keywordstool) | 3,120 | 1,725 |
| 온도메인 통과 | 1,369 | 249 |
| 실검색량 합 | 1,410,120 | 355,304 |
| 1 인지 | **34.8%** (446개) | **70.5%** (96개) |
| 2 탐색 | **58.3%** (654개) | 26.1% (96개) |
| 3 비교 | 3.1% (73개) | **0.0% (0개)** |
| 4 검증 | 1.7% (38개) | 0.6% (6개) |
| 5 행동 | 2.1% (164개) | 2.8% (51개) |
| 단독 대상어 추정 | 50.2% | 59.8% |

### 발견 1 — 피라미드는 법칙이 아니다. 업종이 선언해야 한다.
미용피부과는 1단계 < 2단계로 **뒤집혔다.** 처음엔 사전 버그로 의심했으나,
같은 사전으로 돌린 두통한의원이 70.5% > 26.1% 의 교과서적 피라미드를 냈다.
→ 사전은 멀쩡하고, **미용은 수요가 해결책(시술명)에서 시작하는 시장**이다.

그래서 `demand_shape` 를 업종 사전이 선언하게 했다:
- `problem_led` (질환·통증): 1 ≥ 2 ≥ 3 ≥ 4 — 아파서 검색이 시작된다
- `solution_led` (미용·선택시술): 2 ≥ 1, 2 ≥ 3 ≥ 4 — 시술명에서 검색이 시작된다

무엇이 정상인지를 코드가 아니라 사전이 정한다. 선언과 실측이 어긋날 때만 경고한다.
**영업 함의**: 미용 고객에게 "인지 단계 콘텐츠부터" 라고 말하면 틀린 조언이다.

### 발견 2 — "미분류 0%" 는 가짜 지표다
단독 대상어 fallback(`bare_*`)이 전부 삼켜서 미분류가 0% 로 찍힌다.
정직한 지표는 **`bare_rate` — 의도어를 실제로 맞춘 게 아니라 추정한 몫**이고, 실측 50~60%다.

이건 사전이 얇아서가 아니라 **한국어 검색어 절반이 그냥 복합명사**이기 때문이다
(`모공각화증`, `켈로이드흉터`, `울쎄라`). 의도어 자체가 없다.

→ **SERP 검증(§3.4)의 대상은 여기다.** 이미 의도어로 확신하는 키워드가 아니라,
`bare_*` 중 볼륨 상위를 골라 SERP 구성으로 단계를 확정한다. 30콜 예산의 최적 배치가 이걸로 정해졌다.

### 발견 3 — 두통 축에 "비교" 단계가 통째로 없다 (0개)
사전 결손이 아니다. 미용에서는 같은 사전이 73개(`포텐자가격`, `프락셀가격`)를 찾아냈다.
한방 두통 시장에는 비용·보험 검색이 사실상 존재하지 않는다는 실측이다.
해울 계정에서 비교 단계 콘텐츠를 기획하는 건 헛수고다.
(단, `bare_rate` 가 높으므로 SERP 검증 전까지는 잠정 결론으로 둔다.)

### 발견 4 — substring 함정은 예고대로 터졌고, 위치 규칙으로 막았다
실측에서 잡힌 것들:

| 오탐 | 원인 | 조치 |
|---|---|---|
| `물광주사` → 5단계 행동 | 물[**광주**]사 | 지역 위치 규칙 |
| `고양이주름` → 5단계 | [**고양**]이주름 | 충돌목록 |
| `이명의원인` → 4단계 검증 | 이[**명의**]원인 | 충돌목록 |
| `익산한의원` → 2단계 | 익산 지역 미등재 | REGION_TOKENS 보강 |
| `온다`(브랜드) | "온다" 어미와 충돌 | 사전 위생 점검이 사전 차단 |

**위치 규칙**: 지역명은 키워드 맨 앞이거나 띄어쓰기 직후에만 온다.
충돌목록은 사후 대응이고 위치 규칙이 사전 예방이다. 둘 다 건다.
`audit_lexicon()` 이 2글자 anchor·범주 충돌·자기충돌을 실행 전에 잡는다.

### 발견 5 — keywordstool 레이트리밋
동시 3 + 0.35s 간격으로 시드 14개 중 5개가 429 로 **통째 유실**됐다(조용히 0행 반환).
직렬 + 1.2s + 429 백오프 재시도로 전량 회수. P1 워커도 같은 페이스로 가야 한다.

### P0 판정
- ① 피라미드 — **조건부 통과.** `demand_shape` 선언 후 두 업종 모두 기대 형태와 일치
- ② 대표 키워드 가독성 — **통과.** 3단계는 전부 `~가격`, 4단계는 전부 `~후기`, 5단계는 전부 지역+
- ③ 미분류 ≤ 30% — **통과(0%)이나 무의미.** 대신 `bare_rate` 50~60%를 실질 지표로 승계

→ **P1 진행 가능.** 단, SERP 검증을 "옵션"이 아니라 필수 층으로 승격할 것(발견 2).

## 13. 최종 산출물은 여정 맵이 아니라 "잡아야 할 키워드 표" (2026-08-10)

리스닝마인드의 네트워크 그래프는 **구조를 보여주는 도구**지 답을 주는 도구가 아니다.
`커피머신 추천` 에서 선이 수백 개 뻗어 있어도 "그래서 우리가 뭘 잡나"는 마케터 몫으로 남는다.
그래서 그건 대행사의 도구고, 원장님의 도구가 아니다.

우리 고객은 원장님이다. 원장님이 원하는 건 그래프가 아니라 **"이 27개 쓰세요"** 한 장이다.
→ 여정 맵은 중간재. 최종재는 `scripts/journey_priority.py` 가 뽑는 우선순위 표다.

### 목록은 반드시 3개로 쪼갠다 (하나로 합치면 전부 망가진다)

하나의 종합점수로 합치면 볼륨 큰 1·2단계가 항상 이겨서
"모공 원인 글 쓰세요"만 남고, 예약을 만드는 `포텐자가격`·`분당여드름피부과`는 목록 밖으로 밀린다.

| | 무엇 | 정렬 |
|---|---|---|
| ① 유입용 | 사람을 데려오는 키워드 | 볼륨 × 뚫림 |
| ② 전환용 | 예약을 만드는 키워드 | 볼륨 × 뚫림 × 전환근접(3·4·5단계 가중) |
| ③ 우리 지역 | 볼륨 무관 전량 | 지역 일치분만, 볼륨순 |

### ★ 핵심: 업종만으로는 답이 안 나온다. 지역이 있어야 한다.
실측에서 전환용 상위가 `대구여드름흉터`·`잠실여드름`·`서울흉터치료` 로 채워졌다.
**분당 병원에게 대구 키워드는 가치가 0이다.** `--region` 필터로 153개를 걷어내야 목록이 쓸모를 갖는다.

리스닝마인드는 전국 검색 데이터라 이 필터를 줄 수 없다.
우리는 광고 계정에서 그 업장의 지역을 이미 알고 있다 — **버티컬 + 로컬이 우리 자리다.**

### ③ 을 따로 뽑는 이유
`분당여드름피부과` 930 은 `포텐자후기` 6,040 보다 볼륨이 6배 작아 통합 랭킹에선 영원히 밀린다.
하지만 검색한 사람이 **이미 우리 동네에서 병원을 찾고 있다** — 전환률이 다른 축이다.
볼륨 순위에 맡기면 안 되는 유일한 그룹이라 분리한다.

### 점수 설계에서 배운 것
- **log10 은 볼륨을 너무 누른다.** 150 과 6,040 이 2.2 대 3.8 로 붙어서, 전환가중을 곱하자
  볼륨 150짜리(`대구모공각화증`)가 6,040짜리(`포텐자후기`)를 이겼다. → `sqrt` 로 교체
- `comp_idx` 는 **광고 입찰 경쟁도**다. 블로그 SEO 난이도가 아니다. 지금은 근사치일 뿐이고,
  진짜 뚫림은 `serp_difficulty` + `exposure_ceiling` 을 붙여야 한다 (P1의 핵심 작업)
- 신뢰계수: `bare_*`(단독 대상어 추정)는 0.7 로 깎는다. 단계가 확정이 아니기 때문

### 남은 구멍 (P1 에서 반드시 메울 것)
1. **이미 1페이지를 먹고 있는 키워드를 못 뺀다** — `rank_checker` 연결 전까지 "이미 하는 것"이 섞인다
2. **뚫림이 광고 경쟁도 근사** — SEO 난이도로 교체 필요
3. `여드름연고`·`흉터제거연고` 가 유입 상위를 점령 — 약국 수요일 수 있다.
   병원 방문 의도인지 SERP 로 확인하고, 아니면 trap 으로 내릴 것

### 그래프는 만들 수 있는가 (영업용)
클릭스트림 간선은 복제 불가지만, **자동완성 부모-자식 관계는 방향성 있는 확장 경로**다.
`모공` → `모공축소` → `모공축소비용`. `services/naver_autocomplete.py` 가 이미 그 트리를 만든다.
클릭스트림과 다르지만 화면상 유사하고 "사람들이 어떻게 좁혀가는가"를 근사한다.
**용도 분리**: 그래프는 데모·영업용, 표는 실사용. 표가 없으면 그래프는 팔리기만 하고 쓰이지 않는다.

## 14. "지역 + 업종 → 키워드 전량" 이 되는가 (2026-08-10 · 비의료 대조군)

제품 형태 확인: 업장이 **위치와 업종만 고르면** 3개 목록이 나오는가.
의료 밖에서도 되는지 보려고 `필라테스` 축을 새로 넣고 돌렸다.

### 되는 것 — 공통 의도어는 업종을 넘어 그대로 전이된다
`STAGE_LEXICON` 을 **한 줄도 고치지 않고** 필라테스에서 이게 잡혔다:

- 3단계 비교: `필라테스가격`, `기구필라테스가격`, `골반교정비용`, `재활운동센터비용`
- 5단계 행동: `송도필라테스`, `송도체형교정`, `송도PT`, `건대필라테스`
- `--region 송도,연수,인천` → 남의 동네 29개 제거 후 ③ 목록 정상 산출

**업종마다 새로 만들어야 하는 건 `anchor` 와 `trap` 뿐이다.** 의도어·지역·점수는 공용이다.

### 되지 않는 것 — 사전 초안은 반드시 실측 1라운드로 교정해야 한다
새 업종을 넣자마자 두 가지가 터졌고, 둘 다 **사람의 사전 추측이 틀렸다**는 형태였다.

1. **수요형태 선언이 반증됐다.** `필라테스`를 `solution_led` 로 선언했으나
   실측은 1단계 55.3% > 2단계 39.4% 의 `problem_led` 였다.
   (뱃살·거북목이 불편해서 시작하는 시장이지, 필라테스를 알고 시작하는 시장이 아니다)
   → **`demand_shape` 를 사람 선언이 아니라 실측 판정으로 바꿨다.** 선언과 다르면 경고한다.
2. **trap 미숙으로 제품 쇼핑이 통과했다.** `거북목교정기`(17,630), `거북목베개`, `자세교정밴드`
   가 유입 상위를 점령했다. 스튜디오 고객이 아니라 쿠팡 고객이다.
   또 `손목통증`·`발목통증` 이 새어들어왔다 — 손[**목통증**], 발[**목통증**] substring.
   (지역에는 위치 규칙을 걸었지만 anchor 는 여전히 순수 substring이다. 한국어 복합어는
   `여드름흉터`처럼 anchor 를 정당하게 품기 때문에 위치 규칙을 쓸 수 없고, trap 으로 막아야 한다)

### 사전 성숙도가 통과율로 그대로 드러난다

| 업종 | 수집 | 온도메인 | 통과율 | 사전 상태 |
|---|---|---|---|---|
| 미용피부과 | 3,120 | 1,369 | **44%** | 2라운드 교정됨 |
| 두통한의원 | 1,725 | 249 | 14% | 1라운드 |
| 필라테스 | 3,018 | 286 | **9.5%** | 초안, 미교정 |

통과율이 곧 사전 품질 지표다. P1 에서 이걸 사전 대시보드에 노출할 것.

### 그래서 제품은 이렇게 되어야 한다
"아무 업종이나 자유입력 → 즉시 결과" 는 1일차에 불가능하다. 정직한 형태는:

- **준비된 업종**: 즉시 결과 (캐시 hit, 원가 0)
- **새 업종**: LLM 이 anchor/trap 초안 생성 → keywordstool 실측 → `audit_lexicon()` +
  수요형태 자동판정 + 통과율 검사 → 기준 미달이면 사람이 1라운드 교정 → 캐시 등재
  체감 리드타임 수 시간~1일. UX 는 "우리 업종 신청" 큐로 정직하게 처리한다.

진료과 20여 개 + 지역 서비스업 20여 개면 국내 로컬 광고 수요의 대부분을 덮는다.
사전은 한 번 만들면 그 업종의 모든 업장에 재사용된다 — **§5 의 캐시 경제가 사전에도 그대로 적용된다.**

## 15. 연관도 — "이게 우리 회사 얘기인가" (2026-08-10)

전량 산출물에 `우리연관도(0~100)` 와 `연관근거` 열을 붙였다.

### 새로 만들지 않았다 — 이미 있는 엔진을 꺼냈다
`routers/naver_ad.py::_compute_relevance_score` (0~100 n-gram 원자 점수)는
광고주 6개 계정에서 등록 게이트로 실전 검증된 코드다.
12,000줄 라우터를 import 할 수 없어 순수 로직을 `services/keyword_relevance.py` 로 뽑았다.
⚠ 현재 두 곳에 같은 코드가 있다. 배포 여유가 생기면 라우터가 이 모듈을 import 하도록 정리할 것
(naver_ad.py 에 미커밋 변경이 있어 지금은 건드리지 않았다).

### 연관도는 구매의도가 아니다 — 두 축을 곱해야 한다
```
여드름연고  연관 100  ·  하지만 약국 수요일 수 있다
포텐자후기  연관 100  ·  그리고 병원 방문 직전이다
```
연관도는 "우리 얘기인가", 여정 단계는 "얼마나 살 준비가 됐나"를 잰다.
`convert_score = sqrt(볼륨) × 뚫림 × 신뢰 × 전환근접 × (연관도/100)`

### 실측 — 업종이 아니라 그 업장의 것만 남는다
`--business 포텐자,모공축소,여드름흉터,리프팅,피부과,레이저토닝` 으로 돌리자
`눈밑지방재배치`(58,730)·`울쎄라`(39,860)·`리쥬란효과`(21,490)가 **연관 0**으로 내려앉았다.
미용피부과 업종 키워드인 건 맞지만 **이 병원이 파는 게 아니다.** 정확한 동작이다.

### ★함정: 복합어만 적으면 점수가 안 나온다
`모공축소` 만 시드로 주면 `모공각화증`(40,000)은 2글자 원자 `모공` 으로 **5점**밖에 못 받는다.
n-gram 원자 배점이 3글자 이상 20pt / 2글자 5pt 이기 때문이다.

→ `--expand-seeds`: 업종 사전 anchor 중 입력과 겹치는 **머리어를 시드로 승격**한다.
   `모공축소` → `모공`, `여드름흉터` → `여드름`·`흉터`, `리프팅` → `실리프팅`

| | 강함(80+) | 보통(20~79) | 무관(0~19) |
|---|---|---|---|
| 확장 전 | 338 | 170 | 708 |
| 확장 후 | **769** | 30 | 417 |

**업장에게 "뭘 파세요?"를 물을 때 복합어만 받으면 안 된다.** 머리어까지 자동 승격이 필수다.

### 이 점수를 하드 게이트로 쓰지 말 것
2글자 원자가 5점씩 쌓여 무관 키워드가 문턱을 넘는다.
해울 계정에서 실제로 이 경로로 오염이 통과한 전례가 있다
(explode 는 앵커로 엄격, register 는 이 점수로 느슨 → 우회로가 뚫렸다).
**하드 게이트는 anchor, 이 점수는 정렬·표시용.** `--min-relevance` 기본값을 0 으로 둔 이유다.

## 16. 모든 자영업자로 확장 — 무사전 모드 (2026-08-10)

원장님만이 아니라 자영업자 누구나 자기 키워드를 봐야 한다.
그러면 L0 사전층이 병목이다 — 자영업 업종은 수백 개고 사람이 사전을 다 만들 수 없다.

### 실험: 사전 없이 단어 5개만 받으면 어디까지 되나
`--business 인테리어,리모델링,욕실공사,주방공사,중문설치` (사전 없음)

```
수집 3,662 → 온도메인 1,131 (통과율 30.9%) → 우선순위 959개

② 전환용 상위        화장실리모델링비용 3,590 · 인테리어견적 1,900 · 욕실리모델링비용 1,590
④ 가격·비용 축       83개 / 34,172회 (10.3%)
④ 잘하는곳·추천 축    7개  ·  예약·방문 축 3개
```

**성립한다.** 자영업자가 단어 다섯 개 적으면 959개 우선순위 목록이 나오고,
전환용 상위가 전부 `~비용`·`견적` 이다 — 인테리어 업체가 정확히 원하는 축이다.

무사전 모드를 떠받치는 건 `COMMON_TRAP` 이다. 오염은 업종을 안 가리고 네 덩어리로 수렴한다:
**쇼핑 · 구인/창업 · 정보/학습 · 무료/중고.** 이 넷만 걷어내면 즉석 사전이 돈다.

### 대가는 명확하다 — 의도 확정률이 무너진다

| | 사전 있음 (미용, 2라운드) | 무사전 (인테리어) |
|---|---|---|
| 통과율 | 44% | 30.9% |
| **의도 불명 축** | 56.8% | **88.3%** |
| **의도 확정률** | 43% | **11.7%** |

사전이 없으면 "의도 분석"이라 부를 수 있는 몫이 1/4로 준다.
`거실인테리어`·`현관인테리어` 처럼 공간+업종 복합명사뿐이라 의도어가 아예 없기 때문이다.

### ★ 그래서 SERP 층은 선택이 아니라 확장의 전제다
SERP 상단 구성 파싱 하나가 **두 문제를 동시에 푼다**:

1. **의도 확정** — 상단이 지식인·블로그면 정보형, 파워링크·플레이스면 거래형
2. **trap 자동 생성** — 상단이 쇼핑탭·스마트스토어면 그건 팔 대상이 아니다.
   `거북목교정기`(필라테스에서 유입 1위를 먹었던 오염)를 사람이 손으로 넣지 않아도 걸러진다

즉 **사전 자동화(L0)와 의도 확정(L2)이 같은 부품 하나로 해결된다.**
"모든 자영업자" 를 하겠다면 SERP 층의 우선순위는 1번이 아니라 0번이다.

### 사전의 역할이 바뀐다
사전은 **필수 관문이 아니라 정확도 부스터**다.
→ 제품은 처음부터 모든 자영업자에게 열 수 있고, 사전이 있는 업종은 더 정확할 뿐이다.
   "준비된 업종만 됩니다" 보다 훨씬 나은 제품 이야기이고, 사전은 수요가 몰리는 업종부터 자라면 된다.

### 이번에도 substring 함정이 나왔다 — 이번엔 의도어 쪽
`안경원인테리어`·`수학학원인테리어`·`남원인테리어` 가 1단계(인지)로 샜다.
`~원 인테리어` 가 통째로 **`원인`** 으로 읽힌 것이다.
업종을 하나 열 때마다 이 계열이 새로 나온다 → 사람 눈 검수 1라운드는 당분간 못 없앤다.
