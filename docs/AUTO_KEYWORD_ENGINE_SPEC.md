# 업장 설명 한 줄 → 관련 키워드 10만 자동 추출 설계서

> 작성 2026-08-13. 근거는 전부 이 저장소의 프로덕션 실측이다.
> 추정은 "추정"이라고 쓴다. 근거 없는 상수는 §9에 모아 표시한다.

---

## 0. 30초 요약

사용자는 **업장 설명 한 줄과 지역**만 입력한다. 나머지는 엔진이 한다.

핵심 전환은 이것이다 — **발굴은 이미 해결됐다. 문제는 판정이다.**

자모 접두사 확장은 지금도 12~17배를 낸다(2026-08-13 재측정). 그런데 프로덕션은
해울 최근 등록의 98%, 소잠의 75%가 광고주와 무관했다. 캐낸 게 없어서가 아니라
**"이게 이 업장 것인가"를 판정하지 못해서**다.

그래서 이 설계의 무게중심은 발굴이 아니라 **판정층(L2)** 과 **자가 학습(L4)** 에 있다.

## 1. 왜 지금까지 안 됐나 — 실측 진단

| 관측 | 값 | 출처 |
|---|---|---|
| 자모 확장 수확 | 두통 10→122, 임플란트 8→137 | 2026-08-13 재측정 |
| 해울 최근 등록 중 무관 | 98% (59/60) | recent-registered |
| 소잠 최근 등록 중 무관 | 75% (45/60), 당일분은 94% | recent-registered |
| 소잠 무관 재고 | 감사 23,528 → 실제 132 | §2-3 참조 |
| 메디론 실검색 없는 등록 | 81.8% (74,569/91,175) | low-volume dry-run |
| 계정 키워드 상한 | 100,000 (code 3912 를 200 OK 안에 숨김) | 기존 메모 |

### 1-1. 실패는 전부 판정 실패였다

- `푸마러닝화`가 한의원 시드로 승격됐다 → **승격 게이트가 fail-open**(수정·배포 완료)
- `여드름치료비용자금추천후기비용후기상담` 이 관련성 **100점**을 받았다 → 조합 폭발을
  거르지 못함(수정·배포 완료)
- 감사가 `얼굴뾰루지`·`귀두포피염`을 **무관으로** 셌다 → 사전 결손
- 삭제 후보에 `코트러블`(코 트러블)·`치킨여드름`·`골드PTT피부과`·`화병`(火病)·
  `어린선물섭취`(어린선)·`경면주사팔찌`(한약재)가 들어왔다 → **substring 함정**

### 1-2. substring 함정은 사전으로 못 막는다

이번 한 세션에서만 새 함정이 4라운드 연속으로 나왔다. 기존 메모에도 같은 기록이 반복된다
(`곡성`→도곡성장 160개, `종기`→파종기, `백선` substring, 안경`원인`테리어, 손/발`목통증`).

**한국어는 띄어쓰기가 없어 부분일치가 원리적으로 안전하지 않다.** 사전을 키우는 방식은
함정을 따라잡지 못한다. 판정 근거를 문자열 밖에서 가져와야 한다 → §3.

### 1-3. 10만은 목표가 아니라 상한이다

한 업종의 클린 우주는 5~8만에서 포화한다(해울 48%에서 dry_streak 51, 리베리 발굴 포화,
키네스 진짜 발굴형 505개). 10만을 채운 계정은 **도메인을 버려서** 채웠다.
정당하게 10만에 도달하는 유일한 경로는 §5(지역 곱하기)다.

## 2. 입력 — 사용자가 하는 일은 여기까지

```json
{
  "business": "분당에 있는 피부 전문 한의원. 아토피·습진·무좀·완선을 한약과 약침으로 치료",
  "region": "분당",
  "region_scope": "national | metro | local",
  "homepage": "https://... (선택)"
}
```

`homepage` 가 있으면 본문에서 취급 항목을 추출해 초안 정확도를 올린다(선택).
그 외 추가 입력은 요구하지 않는다. 사전·시드·함정어는 전부 엔진이 만든다.

## 3. 계층 구조

```
L0  도메인 사전 초안      업장 설명 → anchor / trap / 취급항목      (LLM 1회)
L1  발굴                자모 자동완성 · Bing · keywordstool · 조합   (해결됨)
L2  판정 ★              경계매칭 → SERP 실측 → LLM(잔여)           ← 이 설계의 본체
L3  슬롯 경제           실검색·전환근접 우선순위, 10만 배분
L4  자가 학습 ★          판정 결과를 사전에 되먹임, 함정 자동 축적
```

### L0. 도메인 사전 초안 — 기존 자산 재사용

`flyio-backend/data/journey_lexicon.py` 가 이미 anchor/trap 구조를 갖고 있다.
검색 여정 맵 P0 에서 검증된 결론을 그대로 승계한다:

- **공통 의도어는 업종을 넘어 전이된다.** 업종마다 새로 만들 건 **anchor + trap 뿐**
- **사전 초안은 반드시 실측 1라운드 교정이 필요하다.** 필라테스를 solution_led 로
  선언했다가 실측이 problem_led 로 반증한 전례가 있다 → **사람 선언이 아니라 실측 자동판정**

그래서 L0 의 산출물은 "확정 사전"이 아니라 **초안**이다. 확정은 L2 실측 뒤에 한다.

### L1. 발굴 — 이미 되는 것을 그대로 쓴다

| 채널 | 상태 | 근거 |
|---|---|---|
| 자모 접두사 자동완성 | **주력** 12~17배 | 2026-08-13 재측정 |
| Bing 서제스트 | 보조 +40% | naver_autocomplete.py 주석 |
| keywordstool 연관 | 보조. **에코 많음** | 키네스 실측 진짜 발굴 505개뿐 |
| 조합 생성(지역×머리어) | 수율 7.7% | 해울 W2 |
| 네이버 st=111 등 | **효과 없음** | 전 파라미터 동일(재확인) |
| 구글 서제스트 / 다음 | **불가** | 차단 / 404 |

> 새 채널을 찾는 데 시간을 쓰지 않는다. 2026-07-29 표면 조사와 2026-08-13 재측정이
> 같은 결론을 냈다. 병목은 여기가 아니다.

## 4. L2 판정층 — 이 설계의 본체

세 단계를 **비용 오름차순**으로 통과시킨다. 앞 단계에서 확정되면 뒤로 안 넘긴다.

### 4-1. 1단 — 경계 인식 매칭 (무료, 전수)

부분일치를 금지하고 **경계 조건**을 요구한다.

```
토큰이 유효한 매칭이 되려면:
  · 문자열의 맨 앞이거나
  · 띄어쓰기 직후이거나
  · 문자열의 맨 뒤이거나
  · 알려진 조사/접미(의·에·는·이·가·용·점·원) 앞
```

`코트러블` 에서 `코트` 는 뒤에 `러블` 이 이어져 경계가 아니다 → 매칭 안 됨.
`하체비만청바지` 의 `청바지` 는 맨 뒤 → 매칭.

**그리고 양방향 우선순위를 고정한다: ON 토큰이 하나라도 있으면 OFF 판정을 이긴다.**
이번 세션에서 `치킨여드름`·`골드PTT피부과`·`탈모맥주효모`를 살린 규칙이 이것이다.

1단의 출력은 3분류다: `ON확정` / `OFF확정` / **`판정불가`**.
판정불가를 숨기지 않는 것이 중요하다 — 여정 맵 P0 의 교훈("미분류 0%는 가짜 지표")이다.

### 4-2. 2단 — SERP 실측 판정 (핵심)

> 검색 여정 맵 설계서 §16 이 이미 같은 결론에 도달했다: **"SERP 층이 우선순위 1번이
> 아니라 0번"** — 상단 구성 파싱 하나가 의도 확정과 trap 자동생성을 동시에 푼다.

판정불가 키워드를 **실제로 검색해서** 결과 화면 구성으로 판정한다.

| 상단 구성 | 판정 | 예 |
|---|---|---|
| 쇼핑탭 우선 / 가격비교 | **OFF** — 파는 물건이지 진료 대상 아님 | 하체비만청바지, 거북목교정기 |
| 플레이스(병원·의원) 우선 | **ON** + 전환 근접 | 분당피부과 |
| 지식iN·블로그 증상 문서 | **ON** — 정보 탐색 | 코트러블, 얼굴뾰루지 |
| 뉴스·인물·지역 | OFF | |

**이 층이 사전을 대체한다.** `코트러블`이 왜 온도메인인지 사람이 사전에 적어줄 필요가
없다 — 검색해 보면 피부 문서가 나온다. 함정은 무한하지만 SERP 는 유한한 관측이다.

**비용 통제 (필수)**
- SERP 조회는 비싸다. **판정불가 중 실검색량 상위**에만 쓴다
- 결과는 **키워드 단위 영구 캐시**. 같은 키워드를 두 번 검색하지 않는다
- 캐시는 **업종 공용**이다. `하체비만청바지`는 어느 광고주에게나 OFF다
  → 광고주가 늘수록 신규 조회량이 줄어드는 구조 (여정 맵의 무료화 근거와 동일)
- 반드시 **사전 계산 + 큐**. 조회 시점 계산 금지 — 1위 가능 키워드가 요청 1건으로
  `/health` 를 30초로 밀어 전 서비스를 마비시킨 전례가 있다

### 4-3. 3단 — LLM 판정 (잔여만)

SERP 로도 애매한 것만 배치로 넘긴다. 프롬프트에 업장 설명과 취급 항목을 넣는다.
**전수 금지** — 비용이 선형으로 늘고, 이미 L2-1/L2-2 가 대부분을 확정한다.

## 5. 10만 도달 경로 — 지역 곱하기

한 업종의 클린 우주가 5~8만이라는 실측이 반복 확인됐다. 그런데 **지역 축은 아직 안 열렸다.**

```
피부 축 핵심어 5,000 × 전국 지역 200개 = 조합 100만
  → 실볼륨 필터 → 10만 확보 가능
```

근거: 해울 W2 에서 **지역×진료어 축이 조합 최고 수율 7.7%** 를 냈다(기존 조합뱅크 1.5~2%).
그리고 지역 키워드는 **검색량과 무관하게 전량 확보가 원칙**이다 — 검색한 사람 거의 전부가
실제 방문 가능 범위에 있기 때문이다(여정 맵 결론).

**단 `region_scope` 로 제한한다.**
- `local` (기본): 우리 지역 + 인접 생활권만. 분당 병원에 대구 키워드는 가치 0
- `metro`: 광역권
- `national`: 전국 지점이 있는 경우만

> ⚠️ 지역 토큰은 **앞/뒤 앵커 매칭 필수**. `곡성`이 `도곡성장` 160개를 삼킨 사고가 있다.
> §4-1 경계 규칙을 지역에도 그대로 적용한다.

**10만이 안 되면 안 되는 대로 보고한다.** 억지로 채우면 지금 상태(메디론 81.8%가
실검색 없음)가 재현된다. §6 지표가 이걸 막는다.

## 6. L3 슬롯 경제 — 10만은 상한이지 목표가 아니다

계정 상한 10만은 고정이다. 그러면 **무엇으로 채울지가 전부**다.

우선순위:
```
1  우리 지역 × 진료/취급 항목        (검색량 무관 전량)
2  실검색량 ≥ 10 이면서 ON확정        (볼륨 × 뚫림)
3  전환 근접(비용·후기·예약·지역+업종)
4  나머지 ON확정
5  실검색량 < 10                     ← 여유 슬롯이 있을 때만
```

**교체 규칙**: 슬롯이 부족하면 5번부터 밀어낸다. 해울 census 에서 저볼륨 5.2만이 슬롯을
먹어 실볼륨 ≥10 인 두통 키워드 2,721개가 밖에 남아 있던 상황을 막는 장치다.

### 6-1. 지표 교체 (지금 지표는 성공을 과장한다)

| 폐기 | 대체 |
|---|---|
| `fill_pct` = (active+pending)/10만 | **`effective_fill`** = (ON확정 ∧ 실검색≥10) / 10만 |
| DB `active` | 네이버 `ncc_keyword_id` 확인분만 |

근거: 위례해오름은 DB active 122,280 인데 ncc_id 가 붙은 건 42,404 뿐이다.
소잠도 94,933 vs 64,524 로 3만 차이가 난다. **현재 채움률은 실제 등록 기준이 아니다.**

## 7. L4 자가 학습 — "한 번 입력"이 성립하는 이유

이 층이 없으면 사람이 계속 사전을 고쳐야 한다. 이번 세션에서 사람이 4라운드에 걸쳐
찾아낸 함정(코트러블·화병·어린선물·경면주사)을 **엔진이 스스로 찾게** 만든다.

```
SERP/LLM 판정 결과
   → ON 인데 1단이 OFF 로 잘못 판정한 것  → 그 토큰을 anchor 예외로 등록
   → OFF 인데 1단이 ON 으로 통과시킨 것    → 그 토큰을 trap 으로 등록
   → 사전 갱신 → 다음 라운드부터 1단에서 무료로 걸러짐
```

**판정 근거와 함께 저장한다.** "왜 OFF 인가"에 SERP 상단 구성을 남긴다.
근거 없는 판정은 나중에 검증도 되돌리기도 못 한다.

### 7-1. 오염 자기증식 차단 (이미 배포됨)

- 시드 승격은 **anchor 를 모르면 아예 하지 않는다**(fail-closed)
- 조합 폭발·반복 문자열은 시드가 될 수 없다(`is_degenerate_keyword`)
- **추가 필요**: 승격 후보는 L2 에서 `ON확정` 받은 것만. 지금은 1단만 통과해도 승격된다

## 8. 단계별 산출물

| 단계 | 산출물 | 완료 판정 |
|---|---|---|
| **P0** 판정층 코어 | 경계 매칭기 + 함정 회귀 테스트 | 이번 세션에서 나온 함정 12종 전부 통과 |
| **P1** SERP 판정 | 판정 큐 + 캐시 + 상단구성 파서 | 판정불가 1,000건 → 확정률 ≥70% |
| **P2** 자가 학습 | 판정 결과 → 사전 되먹임 | 2라운드째 판정불가 비율이 1라운드보다 감소 |
| **P3** 지역 곱하기 | region_scope 별 조합 생성 | 지역축만으로 실볼륨 ≥10 인 신규 1만 |
| **P4** 슬롯 경제 | effective_fill 지표 + 교체 규칙 | 저볼륨을 밀어내고 고볼륨이 들어오는 게 관측됨 |
| **P5** 한 줄 입력 | 업장 설명 → 전 과정 자동 | 새 업종 1개를 사람 개입 없이 완주 |

**P0 를 먼저 하는 이유**: 판정이 고쳐지지 않으면 발굴을 늘릴수록 오염만 늘어난다.
지금 상태에서 발굴을 키우면 소잠·해울이 더 빨리 망가진다.

## 9. 근거 없는 상수 / 미검증 가정

| 항목 | 값 | 상태 |
|---|---|---|
| SERP 판정 신뢰도 | 70% 목표 | **미측정.** P1 에서 실측해 재보정 |
| 지역 조합 수율 | 7.7% | 해울 1개 업종 실측. 타 업종 미검증 |
| 클린 우주 5~8만 | — | 6개 계정 관측. 업종 편차 미측정 |
| LLM 판정 비용 | — | **미산정.** 3단 진입 비율에 선형 |
| 조합 폭발 판정 임계(범용어 3개) | 3 | 실측 11건/32건으로 정했을 뿐. 표본 작음 |
| SERP 조회 rate limit | — | **미측정.** 차단되면 P1 전체가 막힌다 |

### 9-1. 가장 큰 리스크

**SERP 조회가 막히면 이 설계의 본체가 죽는다.** 네이버는 비공식 경로를 자주 바꾼다.
P1 착수 전에 조회 가능 여부와 지속 가능한 속도를 먼저 재야 한다.
막힐 경우 대안은 ① 사전+LLM 2단 구성으로 후퇴 ② 상위 문서 제목만으로 근사.

## 10. 이 설계가 기존과 다른 점

| 기존 | 이 설계 |
|---|---|
| 마르면 **관련성 기준을 낮춘다**(floor 30→25) | 마르면 **축을 늘린다**(지역 곱하기). 기준은 안 내린다 |
| 사전에 없으면 무관 | 사전에 없으면 **SERP 에 물어본다** |
| 함정을 사람이 찾아 사전에 추가 | 판정 결과가 **함정을 자동 축적** |
| 채움률 = 등록 수 / 10만 | 채움률 = **일하는 키워드** / 10만 |
| 시드 승격 = 검색량 상위 | 시드 승격 = **ON확정 + 검색량** |

> 핵심 한 줄: **기준을 낮춰 채우는 엔진에서, 축을 넓혀 채우는 엔진으로 바꾼다.**
